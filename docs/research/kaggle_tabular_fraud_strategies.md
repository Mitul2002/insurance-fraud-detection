# Winning strategies in Kaggle tabular fraud detection competitions

**The most successful fraud detection competition solutions share a consistent blueprint: entity-level aggregation features outperform exotic encodings, time-aware GroupKFold beats both StratifiedKFold and TimeSeriesSplit, and simple equal-weight ensembles of 3–6 gradient-boosted models outperform complex multi-level stacking.** These findings emerge from analyzing the 1st-place IEEE-CIS Fraud Detection solution (Chris Deotte / FraudSquad, AUC 0.9459, 6,381 teams), the Porto Seguro winner (Michael Jahrer), top Amex Default Prediction solutions, and healthcare fraud detection community work. Pseudo-labeling and domain adaptation remain peripheral in fraud detection — adversarial validation and time-invariant feature engineering are the dominant responses to temporal shift.

---

## 1. Frequency encoding and aggregation dominate over target encoding

Winning fraud detection solutions overwhelmingly favor **frequency encoding and group-level aggregation** over target encoding for high-cardinality categoricals. In the IEEE-CIS 1st-place solution, the team encoded fields like `card1` (~13,000 unique values), `addr1`, and `P_emaildomain` primarily through value counts (`card1_FE`, `card2_FE`) and groupby statistics (e.g., `TransactionAmt_card1_mean`, `TransactionAmt_card1_std`). Target encoding was used as a supplementary technique, not the primary one. The Porto Seguro 1st-place solution by Michael Jahrer explicitly avoided target encoding entirely, instead using **denoising autoencoders (DAEs)** trained on combined train+test features to learn unsupervised representations. His rationale: "Why manually construct 2,3,4-way interactions, use target encoding, search for count features, when a model can find something similar by itself?"

**Temporal leakage prevention** in target encoding follows several patterns. CatBoost's ordered target statistics — used in IEEE-CIS and Amex ensembles — naturally prevent leakage by computing category statistics only from "prior" observations in a random permutation order. When explicit target encoding is used, practitioners apply **Bayesian smoothing à la Micci-Barreca** (the formula `encoded = (n_i × mean_i + m × global_mean) / (n_i + m)` with smoothing parameter `m` typically set between **10 and 100**) or cross-fold encoding where means are computed on K−1 folds and applied to the held-out fold. Many top Kaggle competitors pragmatically compute encodings on the full training set, accepting within-train leakage since train and test are already temporally separated. This works for competitions but requires adjustment for production systems.

**ICD codes are handled fundamentally differently** from simple identifier fields. In the Kaggle Healthcare Provider Fraud Detection dataset (rohitrox), ICD diagnosis codes carry semantic hierarchical structure (mapping to DRG groups), so solutions exploit domain knowledge rather than naive encoding. The dominant approach is **provider-level aggregation**: count of unique diagnosis codes per provider, mean reimbursement per code, and binary indicators for "suspicious" code combinations. Up to 10 diagnosis code columns per claim create a multi-label problem addressed by concatenating all codes into a single series for value-count analysis. Importantly, **no top-voted healthcare fraud notebooks use target encoding for ICD codes** — the provider-level aggregation already captures the relevant signal. Research published in BMC Medical Informatics (2023) used ICD-10 general category codes combined with CPT procedure codes as interaction features in deep autoencoders, detecting anomalous procedure-diagnosis combinations through high reconstruction error.

## 2. GroupKFold by month wins over StratifiedKFold and TimeSeriesSplit

The IEEE-CIS 1st-place solution used **GroupKFold with 6 months as non-overlapping groups** — not StratifiedKFold, not TimeSeriesSplit, and not pure forward-chaining. Training data covered months 12–17 (December 2017 through May 2018). In each of 6 folds, one month was held out for early stopping while the remaining 5 months were used for training. Each fold's model then predicted on the temporal test set. This approach maximized training data while respecting temporal boundaries at the monthly level.

A rare head-to-head empirical comparison by Julien Beaulieu on the IEEE-CIS dataset revealed **TimeSeriesSplit performed worst**: a single LightGBM scored **0.914**, StratifiedKFold 5-fold scored **0.905**, and TimeSeriesSplit 5-fold scored only **0.899**. TimeSeriesSplit suffered because early folds had severely restricted training data (the expanding window problem). StratifiedKFold inflated CV scores through future data leakage but was still competitive for hyperparameter tuning.

The failure modes of StratifiedKFold on temporal fraud data are well-documented:

- **Future information leakage**: Training on months 14–17 while validating on month 13 lets the model learn from fraud patterns that hadn't yet emerged, producing unrealistically optimistic validation scores.
- **CV-to-leaderboard decorrelation**: CV scores from StratifiedKFold may not correlate with temporal test set performance, leading to poor model selection. Multiple IEEE-CIS participants reported this issue.
- **Feature leakage amplification**: Time-dependent features (running counts, aggregations) computed on the full training set before StratifiedKFold splitting contain future information that compounds the leakage problem.
- **Masking distributional shift**: Fraud patterns evolve — new attack vectors emerge, seasonal effects shift. StratifiedKFold mixes time periods so the model never learns to generalize to genuinely unseen time periods.

For **Amex Default Prediction**, StratifiedKFold was actually appropriate because data was aggregated to one row per customer (monthly statements collapsed via mean/std/last aggregations), which neutralized temporal concerns. The lesson: **match CV strategy to data granularity** — transaction-level temporal data demands time-aware splits, while customer-level aggregated data tolerates standard K-fold. Typical fold count across competitions is **5–6 folds**, with 6 being natural for IEEE-CIS (one per month).

## 3. Entity aggregation and UID construction are the highest-impact features

Across all major fraud detection competitions, **entity-level aggregation statistics** consistently rank as the single most impactful feature family. The IEEE-CIS 1st-place team's critical breakthrough was constructing a **Unique User ID (UID)** from `card1 + addr1 + D1` (card number proxy + billing region + days since card activation). This proxy for client identity enabled powerful per-client aggregation features like `groupby(UID)['TransactionAmt'].transform('mean')` and `transform('std')`. An independent replication documented the incremental impact: adding UID-based aggregations pushed scores from **top 30% to top 2%** (public LB 0.9513 → 0.9543).

**Interaction features between entity columns** were the second most important family. The IEEE-CIS solution combined `card1 + addr1 + P_emaildomain` into a single interaction feature because the combined interaction correlated better with the fraud target than individual features. Specific high-value interactions included `card4_addr1_R_emaildomain` and `card1_addr1_R_emaildomain`. Adding interaction features boosted local validation from a **~0.923 baseline to 0.9634** — a massive improvement.

**Velocity and burst features** were explicitly identified in the IEEE-CIS winning solution as key domain knowledge: number of transactions per cardholder in the last 24 hours, total amount spent in 24 hours, multiple charges from a merchant within a short time span, and multiple online charges in close temporal proximity. The D-columns (D1–D15), representing various timedeltas, were transformed by subtracting from TransactionDT to create constant per-client features that enabled velocity-like aggregations.

**Deviation-from-baseline features** proved critical in the Amex competition. The most impactful features were `last − mean` and `last / mean` for each numerical variable — measuring how much a customer's most recent statement deviated from their historical baseline. Feature expansion went from 190 raw features to ~940 after aggregation, then reduced to ~300 via feature selection. These deviation features effectively compute z-score-like anomaly signals within each entity's history.

**Network/graph-based features** are notably absent from Kaggle winning solutions despite strong theoretical appeal. AWS demonstrated converting the IEEE-CIS dataset into a heterogeneous graph, and Grab's engineering team showed graph features (shared device IDs, Wi-Fi routers) are valuable for fraud detection. However, **the top IEEE-CIS solutions (1st, 2nd, 6th place) did not use graph approaches** — they relied entirely on GBM with manual feature engineering. Graph features remain an industry technique rather than a competition-winning one, likely because the feature engineering approach captures similar signals more efficiently for tree-based models.

**Anomaly scores as features** appeared in Porto Seguro's 1st-place solution, where DAE reconstruction error served as an anomaly indicator fed into supervised neural networks. In electricity fraud detection research, Isolation Forest anomaly scores fed to XGBoost achieved AUC-ROC of 0.999. However, this hybrid approach was not prominent in the IEEE-CIS or Amex winning solutions.

## 4. Simple equal-weight blending consistently beats complex stacking

A striking and consistent pattern across fraud detection competitions: **simple averaging outperforms learned meta-learners**. Porto Seguro's 1st-place winner explicitly stated: "Nonlinear stacking failed, simple averaging works best (all weights=1)." Even tuning linear blending weights failed. The IEEE-CIS 1st-place solution used a simple blend of XGBoost + CatBoost + LightGBM without a learned meta-learner. The Amex 2nd-place team (JuneHomes) found that "stacking had minimal impact." Chris Deotte's Amex 15th-place solution used a flat **50/50 equal-weight ensemble** of LightGBM and Transformer.

The only successful stacking examples use **highly regularized linear meta-learners**. Porto Seguro's 18th-place solution (Joseph Eddy) used L2-regularized logistic regression over 16 base models, reaching CV Gini of 0.2924 — close to the 1st place's 0.2965 with a very different approach. The L2 regularization was essential to prevent overfitting on multicollinear OOF predictions. Multi-level stacking has not been the winning strategy in any major fraud detection competition.

**For ROC-AUC metrics, rank averaging handles calibration differences** between models automatically. Each model's predictions are converted to percentile ranks (0 to 1), then averaged — this makes different calibration levels irrelevant since AUC depends only on ordering. **For PR-AUC optimization, probability averaging is preferred** over rank averaging because PR-AUC is sensitive to actual probability values, especially for the minority class. Models should ideally be calibrated via Platt scaling or isotonic regression before blending. Cost-sensitive base models (`scale_pos_weight` in XGBoost/LightGBM, focal loss in neural networks) provide additional benefits for PR-AUC.

Ensemble diversity in fraud competitions comes from **3–6 diverse base models**: the "big three" GBDTs (LightGBM, XGBoost, CatBoost) plus 1–2 neural networks. Sources of diversity beyond model type include different feature subsets, different categorical representations (one-hot, target encoding, entity embeddings), and critically for imbalanced data, **different resampling strategies**. Porto Seguro's 18th-place solution demonstrated that mixing upsampling, downsampling, and class weighting across base models created prediction diversity that improved the stack — a "downsampling sandwich" technique (balanced bagging with 26 partitions × 5 folds = 130 training iterations) pushed from top 100 to top 20.

## 5. Pseudo-labeling is rare in fraud detection; adversarial validation dominates temporal shift handling

**Pseudo-labeling is not a standard technique in winning fraud detection solutions.** The IEEE-CIS 1st-place, Porto Seguro 1st-place, and Amex top-2 solutions all avoided it. The one notable exception is Chris Deotte's Amex 15th-place solution, which used pseudo-labeling for **knowledge distillation**: LightGBM predictions on test data served as soft labels to train a Transformer model. The large amount of pseudo-labeled test data aided the Transformer in learning, and the final 50/50 LightGBM + Transformer ensemble benefited from this approach. When pseudo-labeling is applied, the canonical Kaggle threshold strategy (from Chris Deotte's Instant Gratification competition work) uses **predictions ≤ 0.01 or ≥ 0.99** — extremely confident predictions only. Academic research (FixMatch, NeurIPS 2020) confirms that higher thresholds (0.95+) consistently outperform lower ones: quality of pseudo-labels matters far more than quantity.

There is **no strong evidence that pseudo-labeling specifically helps with temporal shift** in fraud detection. The theoretical concern is well-founded: pseudo-labeling in the presence of distribution shift can reinforce the model's biased predictions on shifted data rather than adapting to new fraud patterns. No competition writeup demonstrates pseudo-labeling being used to specifically combat temporal drift.

**Adversarial validation is the dominant technique** for handling temporal distribution shift. In the IEEE-CIS competition, multiple solutions trained a classifier to distinguish train from test rows, then either removed features with adversarial AUC > 0.7 or transformed them. TransactionDT (raw timestamp) was the #1 discriminating feature between train and test, leading solutions to create relative time features instead. D-column transformation — converting absolute timestamps to per-client constants by subtracting from TransactionDT — was a key temporal-shift mitigation.

The most powerful temporal shift mitigation is not a modeling technique but **feature engineering that creates time-invariant representations**. Computing frequency encodings and aggregation features on combined train+test data (without labels) implicitly uses test set distribution information and has become standard practice. The IEEE-CIS winning solution computed all groupby statistics on the combined dataframe. This is a principled form of transductive learning: using the unlabeled test set's feature distribution to build better representations, even though no test labels are observed.

## Conclusion

Five patterns emerge with high consistency across major fraud detection competitions. First, **entity-level aggregation features provide more predictive power than sophisticated encoding schemes** — constructing entity identifiers and computing their behavioral statistics (mean, std, count of transaction amounts) is the single highest-ROI feature engineering investment. Second, **GroupKFold by natural time periods** (typically months) provides the best trade-off between training data utilization and temporal validity, outperforming both StratifiedKFold (which leaks future information) and TimeSeriesSplit (which wastes training data). Third, for PR-AUC-optimized systems with 2–7% positive rates, **probability-calibrated base models with simple equal-weight averaging** of 3–6 diverse models outperform complex stacking architectures. Fourth, **adversarial validation combined with time-invariant feature engineering** is far more effective at combating temporal shift than semi-supervised approaches. Fifth, the gap between industry graph-based fraud detection and competition-winning approaches suggests an unexploited opportunity: winning solutions achieve top performance through entity aggregation features that approximate graph signals, but true graph-based features from shared-entity networks remain underexplored in competitive settings.
